LOO-CV for RV analysis: the GJ 4276 system¶

In this notebook we will demonstrate how to carry out leave-one-out cross-validation (LOO-CV) using the Pareto-smoothed importance sampling (PSIS) approximation. We will perform a LOO-CV analysis of CARMENES RV data for the GJ 4276 system (Nagel et al. 2019). We will use the arviz package to do so. We begin by importing the relevant packages:

1. Posterior samples¶

The main object that we require for LOO-CV is the pointwise log likelihood for a set of equally-weighted posterior samples. This can be generated after an RV model fit has been completed by iterating through your equally weighted posteriors and calculating the likelihood function (without summing over data points) for each sample. Alternatively, you can generate model realisations for each sample and calculate the likelihood afterwards.

In this case, we will perform LOO-CV for two different models: a single-planet model and a two-planet model. We load the log-likelihoods here (note that you will need to download the auxiliary data and place it in the appropriate directory):

2. Formatting¶

In order to use the arviz loo function, we need to format our data appropriately. We create an object containing the log likelihoods, together with a placeholder for the posteriors (this is not needed in the LOO-CV calculation, but arviz expects the group to be present).

Note that arviz changed its interface at version 1.0: xarray's DataTree replaced InferenceData, and the per-observation scores returned by loo were renamed from loo_i to elpd_i. The two small helpers below let the rest of the notebook run unchanged under either version.

In [3]:
#arviz changed its interface at version 1.0, so detect which one is installed
_ARVIZ_LEGACY = hasattr(az, 'convert_to_inference_data')
_VAR = 'x' if _ARVIZ_LEGACY else 'y'
print('arviz', az.__version__)

def make_loo_input(loglike):
    #Add a chain dimension so the array is read correctly, and attach a placeholder posterior
    ll = np.expand_dims(loglike, 0)
    if _ARVIZ_LEGACY:
        data = az.convert_to_inference_data(ll, group='log_likelihood')
        data.add_groups(posterior={"placeholder": np.ones_like(ll)})
        return data
    return az.from_dict({'log_likelihood': {_VAR: ll},
                         'posterior': {"placeholder": np.ones(ll.shape[:2])}})

def get_loo_i(result):
    #The per-observation scores are called loo_i before arviz 1.0 and elpd_i from 1.0 onwards
    return np.copy(result.elpd_i if hasattr(result, 'elpd_i') else result.loo_i)

loglike_1pl_data = make_loo_input(loglike_1pl)
loglike_2pl_data = make_loo_input(loglike_2pl)

3. Leave-one-out cross-validation¶

If the Pareto k value exceeds 0.7 for any data point, it is recommended to re-run your RV fit without that data point rather than relying on the PSIS approximation to calculate the expected log predictive density (ELPD). This time, the LOO-CV calculation produced a warning, since two of the data points resulted in a shape parameter k > 0.7. This means that a full refit is required to find an accurate ELPD for these data points under this model. Let's figure out what data points we need to refit:

#Convert the output values of k into a numpy array

#Check which indices yield k>0.7
print(np.argwhere(pareto_k_2pl>0.7))

[[ 4]
 [89]]

So, we need to refit the two-planet model to the dataset two more times, once leaving out the data point at index 4, and once leaving out the data point at index 89. Once this is done, we then evaluate the likelihood of the model fit without that data point on the data point itself. The ELPD for that point is the logarithm of the average likelihood across all posterior samples, i.e. $\mathrm{elpd}_i = \log \left[ S^{-1}\sum_s p(d_i|\theta^s) \right]$, which we evaluate with logsumexp for numerical stability. For illustrative purposes, we have provided the per-data-point log-likelihoods for our RV model fit to the data with each point removed.

In [8]:
#Load the log-likelihoods fit to the data with points 4 and 89 removed, evaluated on the whole data set
loglike_x04 = np.load('auxiliary_data/loglikelihood_idx_4_left_out.npy')
loglike_x89 = np.load('auxiliary_data/loglikelihood_idx_89_left_out.npy')

#The ELPD score for each point is the log of the posterior-mean likelihood of the model
#fit with that data point removed, evaluated on that data point
def elpd_i(loglike_column):
    return logsumexp(loglike_column) - np.log(len(loglike_column))

loo_04 = elpd_i(loglike_x04[:,4])
loo_89 = elpd_i(loglike_x89[:,89])

#Create an array of the ELPD values from arviz, and replace the two problematic entries with the newly-computed values
loo_i_2pl_arviz = get_loo_i(loo_2pl)

loo_i_2pl = np.copy(loo_i_2pl_arviz)

loo_i_2pl[4] = loo_04
loo_i_2pl[89] = loo_89

print(loo_i_2pl)

4. Results and plotting¶

Now we can calculate the difference in ELPD scores between the two models, as well as its standard error:

In [9]:
delta_elpd_i = loo_i_1pl - loo_i_2pl

delta_elpd = np.sum(delta_elpd_i)
se_delta_elpd = np.power(len(delta_elpd_i)*np.var(delta_elpd_i),0.5)

print(f"The difference in ELPD is {delta_elpd:.2f} in favour of the single-planet model, with a standard error of {se_delta_elpd:.2f}.")

The difference in ELPD is 12.37 in favour of the single-planet model, with a standard error of 7.57.
